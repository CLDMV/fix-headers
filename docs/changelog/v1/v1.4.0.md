# @cldmv/fix-headers v1.4.0 Changelog

**Release Date**: September 2026
**Release Type**: Minor
**Branch**: `release/1.4.0`

---

## Overview

Version 1.4.0 is the largest release of fix-headers so far. The package is now built: npm ships a bundled `dist/` and `bin/` instead of the raw `src/` tree, with a 1.2 kB CommonJS wrapper around the ES module build. Header dates can be validated without writing anything (`--check`), `@Date` follows an "oldest wins" rule, and mismatched epochs are repaired. `sampleOutput` gains a unified diff and per-field issues (`--diff`), and `includeFolders` accepts non-recursive entries and no longer processes a file twice when entries overlap.

Two long-standing defaults were also corrected, and both change what a run touches. File discovery no longer skips `node_modules`, `dist`, `build`, `coverage`, `tmp`, `.next` and `.turbo` by name: only the project's ignore files (everything git honours) and your own `excludeFolders` decide. And `@Project` now comes from the project's manifest (`package.json`, `pyproject.toml`, `Cargo.toml`, …) whatever the file's type, so CSS, HTML, YAML, JSON and other files get the project's name instead of a folder name.

**Compatibility.** No API was removed and every existing option keeps its meaning, but the first run after upgrading can process files it used to skip and rewrite `@Project`, `@Filename` and epoch values in existing headers. Read the [Upgrade notes](#upgrade-notes) and run with `--dry-run --diff` (or `--check`) once before writing.

## ✨ Features

### Built `dist/` and `bin/` with tsup ([#56](https://github.com/CLDMV/fix-headers/pull/56), [#65](https://github.com/CLDMV/fix-headers/pull/65))

The package is now bundled with tsup, the same way `@cldmv/vitest-runner` is built, instead of shipping `src/` as-is:

- `dist/index.mjs` (ESM), `dist/index.cjs` (CJS) and `bin/fix-headers.mjs` (CLI) are build artifacts, rebuilt by `prepack` before every pack/publish. `main`, `exports` and `bin` point at them, and `files` ships `dist/`, `types/` and `bin/` (no source maps) instead of `src/` and the root `index.mjs` / `index.cjs` shims.
- `dist/index.cjs` is a thin wrapper that `require()`s `dist/index.mjs` (Node 22.12+ loads ES modules synchronously) and returns its default export, so `require("@cldmv/fix-headers")` still returns the `fixHeaders` function itself. The first build bundled a second full copy of the library into the CJS file; [#65](https://github.com/CLDMV/fix-headers/pull/65) replaced it with the wrapper.
- The output is minified with `keepNames`, so `fixHeaders.name` and stack traces stay readable. Published sizes: `dist/index.cjs` 1.2 kB, `dist/index.mjs` 34.7 kB, `bin/fix-headers.mjs` 43.2 kB.
- Detectors are imported statically instead of being discovered by reading `src/detectors/` at runtime, which a bundle cannot do.
- A `fix-headers-dev` export condition resolves the package to `src/` for development against the source.

Closes [#18](https://github.com/CLDMV/fix-headers/issues/18).

### Header date validation, oldest-wins `@Date` and epoch repair ([#67](https://github.com/CLDMV/fix-headers/pull/67))

`check` / `--check` validates the `@Date` and `@Last modified time` of every existing header, writes nothing, and exits `1` when it finds date drift. The checks compare instants rather than strings, so the same moment written with another offset or in the space/`T` form is not drift, and they run independently of the rendered-header diff, so an author or copyright difference never fails them:

| Check                                | Fails the run                           | Meaning                                                                                  |
| ------------------------------------ | --------------------------------------- | ---------------------------------------------------------------------------------------- |
| `created-format` / `modified-format` | yes                                     | the value is not a recognised `<datetime> (<epoch>)` pair                                |
| `created-epoch` / `modified-epoch`   | yes                                     | the epoch does not decode to the datetime text                                           |
| `created-newer-than-source`          | with `strictCreatedDate`, else advisory | `@Date` is later than the older of the git first commit and the filesystem creation time |
| `modified-git`                       | no (advisory)                           | `@Last modified time` is not the git last-commit date                                    |

`@Date` now follows "oldest wins" across the existing header value, the git first commit and the filesystem creation time (the earlier of birth time and modification time). An `@Date` older than git or the filesystem is correct and is never moved forward.

- A new header takes the older of the git first commit and the filesystem creation time (git wins a tie). Previously the git first commit always won.
- An existing `@Date` is kept as written, except that its epoch is recomputed from the datetime text when the two disagree.
- `fixCreatedDate` / `--fix-created-date` moves an existing `@Date` to the oldest of the three sources, so it only ever moves earlier.
- `strictCreatedDate` / `--strict-created-date` makes `created-newer-than-source` fail `--check` instead of being an advisory.
- `normalizeDateFormat` / `--normalize-date-format` writes every header date in the git `%aI` form (`2026-03-01T17:59:32-08:00`), keeping each date's offset and instant.

Dates read from git are now written with a numeric `+00:00` offset on every git version. Git 2.45 and later print a UTC `%aI` date as `…Z` where older versions print `+00:00`, so the same file could get a different `@Date` or `@Last modified time` text depending on the installed git.

Closes [#31](https://github.com/CLDMV/fix-headers/issues/31).

### Unified diff and per-field issues in sample output ([#66](https://github.com/CLDMV/fix-headers/pull/66))

With `sampleOutput: true`, each changed entry's `sample` now also carries:

- `diff`: a ready-to-print unified diff of the header block (`--- a/<file>` / `+++ b/<file>`, `/dev/null` when the file had no header), with file line numbers in the hunks. It is a small built-in line-level LCS, so the package still depends only on `ignore`.
- `issues`: one `{ field, previous, detected }` entry per header field whose written value differs from the existing header (project name, filename, created date, author name and email, last-modified identity and time, copyright years and company). Preserved fields, such as the author unless `forceAuthorUpdate` is set, only appear when they actually change.

On the CLI, `--diff` prints each changed file's header diff (and implies `--sample-output`), and `--verbose` together with `--sample-output` or `--diff` prints each file's field differences as `field: found "X", expected "Y"`.

Closes [#34](https://github.com/CLDMV/fix-headers/issues/34).

### Non-recursive include folders ([#60](https://github.com/CLDMV/fix-headers/pull/60))

`includeFolders` entries may now be objects, `{ path: string, recursive?: boolean }`. `recursive: false` includes only that folder's own files, so `{ path: ".", recursive: false }` covers the project-root files without walking the whole tree. Plain string entries stay recursive. The CLI gains a repeatable `--include-folder-non-recursive <path>` flag.

## 🐛 Bug Fixes

### `@Project` comes from the project's manifest, whatever the file type ([#72](https://github.com/CLDMV/fix-headers/pull/72), [#75](https://github.com/CLDMV/fix-headers/pull/75))

Each file-type detector used to carry its own marker list and name rule, so the same project produced different `@Project` values per file type: a CSS file always got its folder name even next to a `package.json`, an HTML file got the name of the nearest folder holding `index.html` or a vite/next config (or its own folder), and YAML and JSON files only ever read a `package.json`, so in a Python, PHP, Rust or Go project they fell back to a folder name.

[#72](https://github.com/CLDMV/fix-headers/pull/72) made CSS and HTML read the `package.json` name. [#75](https://github.com/CLDMV/fix-headers/pull/75) then moved project resolution out of the detectors altogether and into per-ecosystem manifest drivers (`node`, `python`, `php`, `rust`, `go` in `src/drivers/`). Detectors now only decide comment syntax.

- The nearest folder any driver claims is the project root: the base of `@Filename` and of git history lookups.
- When several drivers claim that folder, the file's native driver is read first (a `.py` file reads `python` first), then `node`, `python`, `php`, `rust`, `go`. Each field comes from the first manifest that provides it.
- A value missing at the project root climbs to the next claimed ancestor, up to the scan root and never past a folder holding `.git`. Only values climb; the root, and with it `@Filename`, stays the nearest claimed folder. A nameless sub-package (`{ "private": true }`) therefore takes the name of the repository around it.
- Without any manifest name, the project root's folder name is used; with no manifest up to a repository root, that repository root; with neither, the file's own folder.
- The Python driver reads `pyproject.toml` (`[project].name`, then `[tool.poetry].name`), `setup.cfg` (`[metadata] name`, new) and `setup.py`. `requirements.txt` no longer claims a folder: it carries no name and often sits in folders that are not projects (`docs/requirements.txt`).
- `detectedValues` reports `projectNameSource`: `{ from: "manifest", driver, manifest, dir }`, `{ from: "folder", dir }` or `{ from: "option" }`.

Closes [#70](https://github.com/CLDMV/fix-headers/issues/70) and [#74](https://github.com/CLDMV/fix-headers/issues/74).

### Discovery excludes only what ignore files or the consumer exclude ([#73](https://github.com/CLDMV/fix-headers/pull/73))

Discovery used to skip `node_modules` at any depth and `dist`, `build`, `coverage`, `tmp`, `.next` and `.turbo` at the project root by name, whatever the project's own rules said, and it read only the root `.gitignore`. Now nothing is skipped because of its name; `.git` (git's own storage) is the only folder never walked.

"Ignore files" now means everything git honours. Inside a git work tree, one `git ls-files --cached --others --exclude-standard` per repository decides, so nested `.gitignore` files, `.git/info/exclude`, `core.excludesFile` and negations all apply, and tracked files are processed even when an ignore pattern matches them. Outside a work tree (or without git), the `.gitignore` files under the discovery root are parsed, each scoped to its own folder. A nested repository or submodule applies its own rules to its own files, and a discovery root that the enclosing repository ignores is treated as a standalone folder. `gitignore: false` and explicit `gitignore` paths keep working.

The internal `ALWAYS_IGNORE_FOLDERS`, `ROOT_IGNORE_FOLDERS` and `DEFAULT_IGNORE_FOLDERS` constants are gone from `src/constants.mjs`; they were never part of the package's exports.

Closes [#71](https://github.com/CLDMV/fix-headers/issues/71).

### Overlapping include folders process each file once ([#60](https://github.com/CLDMV/fix-headers/pull/60))

`discoverFiles()` walked every `includeFolders` entry independently and concatenated the results, so a file under two entries (`"."` next to `"src"`, `"src"` next to `"src/core"`, or the same folder spelled twice) was returned, and processed with its git lookups, once per entry. One real include list discovered 1920 paths for 963 files. Roots are now canonicalized up front, a root already covered by another is dropped before any walk, surviving roots are walked in input order, and the result is de-duplicated by path. An entry that is neither a string nor `{ path }` now throws a `TypeError` instead of failing inside `path.join`.

Closes [#59](https://github.com/CLDMV/fix-headers/issues/59).

### GPG signer author: UID comment dropped, name taken from the signing key ([#62](https://github.com/CLDMV/fix-headers/pull/62), [#69](https://github.com/CLDMV/fix-headers/pull/69))

With `useGpgSignerAuthor`, the author name kept the OpenPGP user-ID comment, so a key UID `Jane Doe (laptop) <jane@example.com>` produced `@Author: Jane Doe (laptop)`. The comment is now dropped (nested and escaped parentheses included); parentheses elsewhere in the name are kept ([#62](https://github.com/CLDMV/fix-headers/pull/62)).

The option also read the last commit's signer (`%GS`). On a squash-merged branch the tip is a merge made by GitHub or a release bot whose signature cannot be verified locally, so `%GS` was empty and the author silently fell back to `git config user.name`. The name now comes from the user ID of the OpenPGP key git signs with (`user.signingkey`, listed through `gpg.openpgp.program` / `gpg.program` / `gpg`, first user ID that is not revoked or expired). Without a readable OpenPGP key it falls back to `%GS`, `user.name` and the last commit's author as before ([#69](https://github.com/CLDMV/fix-headers/pull/69)).

Closes [#61](https://github.com/CLDMV/fix-headers/issues/61) and [#68](https://github.com/CLDMV/fix-headers/issues/68).

### Header field parsing without polynomial regexes ([#66](https://github.com/CLDMV/fix-headers/pull/66))

CodeQL flagged the `@Last modified by` and `@Copyright` splitters in `src/header/fields.mjs` as polynomial ReDoS (`js/polynomial-redos`): a crafted 20,000-character header value took minutes to parse. Both are now string scans plus anchored, unambiguous regex pieces. They return exactly what the old expressions did (checked against them on 200,000 random values), and 100,000-character adversarial values parse in about a millisecond.

### No more `vitest` peer dependency ([#51](https://github.com/CLDMV/fix-headers/pull/51))

`package.json` declared `vitest >=1.0.0` as a peer dependency since the initial commit, although no shipped file imports it. npm 7+ therefore installed vitest into every consumer's tree. The entry is removed; vitest stays a dev dependency.

## Upgrade notes

There is no API change to make, but several defaults changed. Before the first writing run, preview it: `fix-headers --dry-run --diff --verbose` shows every file that would change and which fields differ, and `fix-headers --check` reports date drift without writing.

- **Files that were skipped by name are now processed** ([#73](https://github.com/CLDMV/fix-headers/pull/73)). `node_modules`, `dist`, `build`, `coverage`, `tmp`, `.next` and `.turbo` are processed unless an ignore file or `excludeFolders` excludes them. Most projects already ignore these in `.gitignore` and see no difference. A project that does not (a committed `dist/`, an unignored `tmp/`, a run with `gitignore: false`, or a folder outside any git repository without a `.gitignore`) will get headers written into those files. To keep them out, add them to `.gitignore` (an anchored pattern such as `/dist/` matches only at the root) or to `excludeFolders` (a bare name such as `"dist"` matches at any depth).
- **Tracked files that match an ignore pattern are now processed**, because git does not treat tracked files as ignored. Conversely, nested `.gitignore` files, `.git/info/exclude` and `core.excludesFile` now apply, so files they ignore are no longer processed.
- **`@Project` can change for CSS, HTML, YAML, JSON and other non-native files** ([#72](https://github.com/CLDMV/fix-headers/pull/72), [#75](https://github.com/CLDMV/fix-headers/pull/75)). They now get the name from the nearest manifest (`package.json`, `pyproject.toml`, `setup.cfg`, `setup.py`, `composer.json`, `Cargo.toml`, `go.mod`) instead of a folder name. Files in a nameless sub-package now take the enclosing project's name, and Python files whose nearest marker was `requirements.txt` resolve to the next real manifest. Pass `projectName` to pin one value for every file.
- **`@Filename` can change for the same files**, because the project root is now the nearest folder a manifest claims rather than the nearest detector-specific marker (for example an HTML file's nearest `index.html` or vite/next config folder, or a CSS file's nearest `postcss.config.*`). Pass `projectRoot` to pin it.
- **Headers with a wrong epoch are rewritten** ([#67](https://github.com/CLDMV/fix-headers/pull/67)). In a writing run, an `@Date` or `@Last modified time` whose `(epoch)` does not match its datetime text gets the epoch recomputed from the text; like any updated file, it also gets a fresh `@Last modified time`. The datetime text itself is left as written.
- **New headers can get an earlier `@Date`** ([#67](https://github.com/CLDMV/fix-headers/pull/67)): the older of the git first commit and the filesystem creation time, where previously git always won. On a fresh clone or CI checkout the filesystem time is current, so git still decides there. Existing `@Date` values are only moved with `--fix-created-date`.
- **UTC dates from git are written as `+00:00`** instead of `Z` on git 2.45 and later ([#67](https://github.com/CLDMV/fix-headers/pull/67)).
- **`useGpgSignerAuthor` can resolve a different name** ([#62](https://github.com/CLDMV/fix-headers/pull/62), [#69](https://github.com/CLDMV/fix-headers/pull/69)): the configured signing key's user ID without its comment, instead of the last commit's signer or the `git config user.name` fallback. Existing `@Author` and `@Last modified by` identities are still preserved unless a `force…` option is set.
- **The package ships `dist/` and `bin/`, not `src/`** ([#56](https://github.com/CLDMV/fix-headers/pull/56)). `import fixHeaders from "@cldmv/fix-headers"`, `require("@cldmv/fix-headers")` and the `fix-headers` binary work as before. Anything that reached into `node_modules/@cldmv/fix-headers/src/…` or the removed root `index.mjs` / `index.cjs` by path must switch to the package entry point. `require()` relies on Node 22.12+, which `engines` has required since v1.3.12.
- **An invalid `includeFolders` entry now throws a `TypeError`** ([#60](https://github.com/CLDMV/fix-headers/pull/60)): anything that is neither a string nor `{ path }`. Overlapping entries no longer produce duplicate entries in `result.changes`.
- **npm no longer installs `vitest` alongside fix-headers** ([#51](https://github.com/CLDMV/fix-headers/pull/51)). A project that relied on getting it that way must declare it itself.
