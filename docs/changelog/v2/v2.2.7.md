# `@cldmv/fix-headers` v2.2.7 Changelog

**Release Date**: November 2026
**Release Type**: Patch
**Branch**: `release/2.2.7`

---

## Overview

Version 2.2.7 changes how the package is tested, not what it does. Nothing under `src/` changed, so header handling, the `fixHeaders` API, the CLI and the published `dist/` behave exactly as in v2.2.6.

The test suite now really runs against `src/` through the `fix-headers-dev` condition (the old config never passed it to the test workers), the same suite also runs against the built `dist/` with `npm run test:dist`, and one discovery test no longer fails when the checkout sits under a folder named `dist`. The rest is a `vitest` 5.1.0 bump and the `sync-release-notes` workflow.

---

## 🧪 Tests

### The `fix-headers-dev` condition reaches the test workers ([#179](https://github.com/CLDMV/fix-headers/pull/179))

The vitest config passed the condition through `test.nodeOptions`, which isn't a Vitest option, so the workers never got it. It now uses `devCondition()` from `@cldmv/configs`, which sets `resolve.conditions`, `ssr.resolve.conditions` and the workers' `execArgv` from the package's own `package.json`.

### `npm run test:dist` runs the suite against the build ([#181](https://github.com/CLDMV/fix-headers/pull/181))

The tests import the package by name (`@cldmv/fix-headers`) instead of `../src/index.mjs`. `npm run test:dist` builds the package and runs the suite with `--mode=dist`, which leaves the `fix-headers-dev` condition off, so those imports load `dist/`. A new `tests/resolve.test.vitest.mjs` checks that each run loaded the tree it meant to. `npm test` and `ci:coverage` now include the `dist/` run.

### Discovery test judges paths from the workspace root ([#182](https://github.com/CLDMV/fix-headers/pull/182))

The include/exclude discovery test checked `path.includes("dist/")` on absolute paths, so it failed whenever the checkout itself sat under a folder whose name ends in `dist`. It now looks at each path's folders relative to the workspace. Because the include-folder walk never visits `dist/`, the test also does a whole-project walk with only `excludeFolders`, so the `dist` exclusion is actually exercised.
