# `@cldmv/fix-headers` v2.2.6 Changelog

**Release Date**: November 2026
**Release Type**: Patch
**Branch**: `release/2.2.6`

---

## Overview

Version 2.2.6 sets `engines.node` back to the Node.js version the package needs at runtime, `>=18.0.0`, instead of the 22.22.0 development toolchain floor that v2.2.5 put there. The 22.22.0 floor moves to npm's `devEngines`, which only applies when you work on this repository.

Header handling, the `fixHeaders` API and the CLI behave exactly as in v2.2.5. Installs on Node.js 18 through 22.21 no longer get an `EBADENGINE` warning.

---

## 🐛 Bug Fixes

### `engines.node` is the runtime floor again ([#176](https://github.com/CLDMV/fix-headers/pull/176))

v2.2.5 raised `engines.node` to `>=22.22.0` because the development toolchain (tsup 9 needs 22.18 or later) no longer runs on older Node.js. The published package doesn't need any of that toolchain, so the floor was stricter than the code. `engines.node` is now `>=18.0.0`, and the bundles are built for `node18` (tsup `target`, was `node22`).

The package is an ES module and loads with `import` on Node.js 18 and later. `require("@cldmv/fix-headers")` loads the ES module build synchronously, which needs `require(esm)`: Node.js ^20.19.0 or >=22.13.0. On a Node.js without it, the CommonJS entry now says exactly that (`require() needs Node.js ^20.19.0 or >=22.13.0`, code `ERR_REQUIRE_ESM`) and points to `import()`; v2.2.5's message asked for 22.22.0.

## 📦 Requirements

- **Runtime:** Node.js 18.0.0 or later (`engines.node` is `>=18.0.0`, was `>=22.22.0`). `require()` needs Node.js ^20.19.0 or >=22.13.0; use `import()` on older versions.
- **Development:** working on this repository needs Node.js 22.22.0 or later, declared in `devEngines.runtime` with `onFail: "error"`. This doesn't affect anyone installing the package.

## 🔧 CI & tooling

- The CI and publish workflows keep `min_node_version` at 22.22.0; its description and a comment now say it's the dev toolchain floor and should match `devEngines`, not `engines` ([#176](https://github.com/CLDMV/fix-headers/pull/176)).
