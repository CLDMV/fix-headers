# `@cldmv/fix-headers` v2.2.5 Changelog

**Release Date**: November 2026
**Release Type**: Patch
**Branch**: `release/2.2.5`

---

## Overview

Version 2.2.5 removes the development check added in v2.2.4 and raises the Node.js floor to 22.22.0. Header handling, the `fixHeaders` API and the CLI behave exactly as in v2.2.4.

The development check only ever ran in a source checkout, never in the installed package, so removing it changes nothing for consumers. The Node.js floor is a real requirement change: `engines.node` is now `>=22.22.0` (was `>=22.13.0`), so installs on Node.js 22.13 through 22.21 get an `EBADENGINE` warning, or fail under `engine-strict`.

---

## 🐛 Bug Fixes

### Development check removed ([#170](https://github.com/CLDMV/fix-headers/pull/170))

v2.2.4 made `src/index.mjs` load a root `devcheck.mjs` that stopped a source checkout run without `--conditions=fix-headers-dev`. That check is gone, along with its test and the tsup `external` entry that kept it out of the bundles. The `fix-headers-dev` export condition already chooses the tree: with it, `@cldmv/fix-headers` resolves to `src/`; without it, to the built `dist/`. Both are valid ways to run a checkout, and the repository's npm scripts and Vitest config pass the condition.

The published `dist/index.mjs`, `dist/index.cjs` and `bin/fix-headers.mjs` no longer reference `../devcheck.mjs` at all; before, they tried to load it and skipped it when it was missing. The entry files stay `src/index.mjs` and its CommonJS sibling `src/index.cjs`, and the package's exports are unchanged.

## 💥 Breaking Changes

### Node.js 22.22.0 or later ([#170](https://github.com/CLDMV/fix-headers/pull/170))

`engines.node` is `>=22.22.0` (was `>=22.13.0`). The development toolchain no longer runs on earlier 22.x releases (tsup 9 needs 22.18 or later), so those versions can't be tested any more. The CI matrix floor, the README requirements and the message `require("@cldmv/fix-headers")` prints on a Node.js without `require(esm)` all say 22.22.0 now. The library code itself didn't change for this; it's a change to what is supported and tested.

- The `katex` and `minimatch` npm overrides from v2.2.4 are unchanged; both are development-only.

## Upgrade notes

- **Node.js 22.22.0 or later is required** (was 22.13.0). Upgrade Node.js before upgrading the package.
- No change to the `fixHeaders` API, the CLI or the output it writes. Upgrading from v2.2.4 produces no diff in your files.
- In a fix-headers source checkout, nothing stops a run without `--conditions=fix-headers-dev` any more; it just uses `dist/`, so build first or pass the condition. The npm scripts already pass it.
