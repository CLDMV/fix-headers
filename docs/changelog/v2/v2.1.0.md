# @cldmv/fix-headers v2.1.0 Changelog

**Release Date**: September 2026
**Release Type**: Minor
**Branch**: `release/2.1.0`

---

## Overview

Version 2.1.0 adds two layout options, `spacing` and `margin`, and by default frames every header with empty comment lines and leaves two blank lines before the file's own content. It fixes line-comment headers (YAML, Python and other `#` languages) losing the bare comment lines that pad the top and bottom of the header, which happened because the parser replaces the whole leading comment run and the line renderer had no top and bottom lines to put back. It also carries a patch-level bump of four dependencies.

No option was removed and the `fixHeaders` API is unchanged. Existing headers are restyled to the new layout on the first run; pass `spacing: 0` and `margin: 1` to keep the previous compact layout.

---

## ✨ Features

### `spacing` and `margin` header layout options ([#101](https://github.com/CLDMV/fix-headers/pull/101))

Both options are top-level settings in a config file, in the `fixHeaders` API and on the CLI (`--spacing <n>`, `--margin <n>`), and apply to every file type:

- **`spacing`** (default `1`) is the number of empty comment lines just inside the header's opening and just before its closing. A block header gets an empty ` *` line under `/**` and above ` */`; a line-comment header gets a bare `#` (or the language's own prefix) above and below the fields.
- **`margin`** (default `2`) is the number of blank lines between the header and the file's next content. A line-comment header always keeps at least one blank line after it, even with `margin: 0`, so a comment that follows the header is not read as part of it.

Both accept any whole number of `0` or more; anything else is rejected before a file is touched. An existing header of any layout is restyled in place, and a second run with unchanged options finds nothing to update. See [Header layout](https://github.com/CLDMV/fix-headers/blob/master/README.md#header-layout) in the README.

Closes [#100](https://github.com/CLDMV/fix-headers/issues/100).

## 🐛 Bug Fixes

### Line-comment headers keep their padded frame lines ([#101](https://github.com/CLDMV/fix-headers/pull/101))

A YAML workflow or Python file that carried the common template header, with a bare `#` line above and below the field block, lost both lines on the first run, and the header then ran straight into the next comment. `renderHeaderLines` now emits the frame lines for line headers as well, controlled by `spacing`. Block headers get the same frame (`/**`, ` *`, fields, ` *`, ` */`), where before `/**` was followed directly by the first field.

## Upgrade notes

- No breaking changes: no option was removed and the API is unchanged.
- The first run after upgrading restyles every header to the new layout: an empty comment line inside the opening and closing, and two blank lines before the file's content. Preview it with `--dry-run --diff --verbose`, or set `spacing: 0` and `margin: 1` to keep the previous compact layout.
