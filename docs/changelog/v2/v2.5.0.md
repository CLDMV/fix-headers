## Overview

Generated TypeScript declarations get a header of their own. `tsc` copies a source file's header into the `.d.ts` / `.d.mts` / `.d.cts` it emits, so the declaration an IDE shows named the source file. fix-headers now restamps such a declaration for the path and package it ships in, keeping the source's dates and author. This is the setup for packages that build `types/` in CI or `prepack` instead of committing it.

---

## ✨ Features

### Generated declarations are restamped for where they ship ([#202](https://github.com/CLDMV/fix-headers/pull/202))

A declaration whose header names its own source (`types/src/x.d.mts` with `@Filename: src/x.mts`) gets `@Filename: types/src/x.d.mts` and its package's `@Project`. `@Date`, `@Author`, `@Last modified by` and `@Last modified time` stay as the source's header has them, since a generated file has no git history of its own. A staged package folder with its own `package.json` is its own project root, so `dist-packages/x-types/lib/x.d.mts` gets `@Filename: lib/x.d.mts` and that package's name. Run fix-headers after `tsc`, for example `fix-headers --input types` in `prepack` or CI.

A later run leaves a restamped declaration as it is when git doesn't track it: a declaration with a header that git doesn't track is treated as generated, so it keeps the editor and dates it carries instead of taking the runner and the current time.

`rewriteDeclarationCopies: false` (CLI `--no-rewrite-declaration-copies`) keeps the 2.4.0 behaviour of skipping these declarations, for repos that still commit `types/`.

Fixes [#201](https://github.com/CLDMV/fix-headers/issues/201).

## Upgrade notes

- **Repos that commit generated `types/`:** set `"rewriteDeclarationCopies": false` in the fix-headers config. Otherwise fix-headers and `tsc` rewrite each other's `@Filename` on every build, as before 2.4.0. The better fix is to gitignore `types/` and build it in CI and `prepack`.
- Repos that don't run fix-headers on declaration files see no change.
