# @cldmv/fix-headers v2.2.1 Changelog

**Release Date**: October 2026
**Release Type**: Patch
**Branch**: `release/2.2.1`

---

## Overview

Version 2.2.1 moves the repository's own development setup to `@cldmv/configs` 1.2.4. Nothing the package ships changed: `dist/`, `bin/`, the generated types and the runtime dependency `ignore` are exactly as in [v2.2.0](./v2.2.0.md). The published package differs only in the `version` field and in the `@cldmv/configs` range recorded in its `devDependencies`.

The shared config is what the repository's own `npm run fix:headers` extends, so the bump changes how fix-headers stamps its own source files. Version 1.2.4 turns off `forceAuthorUpdate` and `forceLastModifiedAuthorUpdate`, which were both on in 1.2.0. With v2.2.0 of the tool, that means `@Author` is never rewritten, and `@Last modified by` changes only when a file's content was edited. The run that accompanied the bump scanned 109 files and changed none.

---

## 🔧 Dependencies

- **`@cldmv/configs` `^1.2.0` → `^1.2.4`** ([#131](https://github.com/CLDMV/fix-headers/pull/131)), dev dependency. The lockfile moves from 1.2.0 to 1.2.4, and that is the only dependency entry that changed. Between those versions the shared `fix-headers.json` switched `forceAuthorUpdate` (1.2.3) and `forceLastModifiedAuthorUpdate` (1.2.4) from `true` to `false`. It is used by `npm run fix:headers` and by nothing that ships.

## Upgrade notes

- No breaking changes, and no behaviour change for consumers: drop-in for [v2.2.0](./v2.2.0.md). The runtime dependency list is unchanged.
- Projects that extend `@cldmv/configs`' `fix-headers.json` should use `@cldmv/configs` 1.2.4 or later together with `@cldmv/fix-headers` 2.2.0 or later. On older versions of the tool, the forced author settings that 1.2.4 turns off behave differently.
