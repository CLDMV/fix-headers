# `@cldmv/fix-headers` v2.2.4 Changelog

**Release Date**: October 2026
**Release Type**: Patch
**Branch**: `release/2.2.4`

---

## Overview

Version 2.2.4 makes a file carry exactly one header. Stacked copies of a header are merged into one whatever their first line is, repeated fields are dropped as duplicates, and a stale `@Copyright` for the same holder goes away while one naming another holder is kept and reported as a warning. Only lines that must stay at the very top of a file (a shebang, a Python encoding line, `#cloud-config`, `@charset`, Go build constraints, `<?php`, Markdown front matter, a Vim modeline) stay above the header, and files where an earlier version wrote the header above such a line are repaired. `#` headers are now found in files with CRLF line endings or a byte-order mark. These are the follow-ups to the v2.2.3 header-text fix, tracked in [#162](https://github.com/CLDMV/fix-headers/issues/162).

This changes what a run writes to files that have a stacked or duplicated header, a stale `@Copyright` line, or a header an earlier version placed above a shebang or directive: the first run after upgrading cleans them up. Files with a single, clean header are written exactly as before.

The rest of the release is packaging and hardening: the entry files are now `src/index.mjs` and `src/index.cjs`, a source checkout run without the `fix-headers-dev` condition stops with a clear message, the Node.js floor is 22.13.0, and two CodeQL ReDoS alerts are fixed.

## 🐛 Bug Fixes

### One header per file ([#166](https://github.com/CLDMV/fix-headers/pull/166), fixes [#162](https://github.com/CLDMV/fix-headers/issues/162))

- **Stacked headers are merged.** A comment is a file header when it holds a `@Project:` or `@Filename:` line. Every file header stacked directly after the first one (blank lines only in between) is merged into it, whatever its first line is and whatever project or file it names. v2.2.3 only merged a stacked comment whose first line was `@Project:`, so one starting with description text was left as a second header.
- **Repeated fields are duplicates.** A second `@Project`, `@Date` or `@Author` line is dropped along with a `-----` line next to it. In v2.2.3 these were kept as text.
- **Additional `@Copyright` lines are compared by holder.** A second `@Copyright` naming the same holder as the regenerated one (a stale `2013-2025` line next to the new `2013-2026` one) is dropped. One naming another holder (`Copyright (c) 2010 Mozilla Foundation`) is kept as a field directly under the header's own and reported: in the result's new `copyrightWarnings` array (`{ file, copyright }`), in each change's `extraCopyrights`, and on the CLI as a `warning: <file> keeps an additional @Copyright: <value>` line with `warnings=<n>` in the summary. The warning never changes the exit code.
- **The v2.2.3 lead line is cleaned up.** A block v2.2.3 moved below the header with the lead line `Moved out of the file header by fix-headers:` and a `@Project:` line is merged as a copy of the header, and the lead line is dropped with its fields. Newly moved blocks no longer get a lead line, because they never hold a `@Project:` or `@Filename:` line.

### Only position-critical lines stay above the header ([#166](https://github.com/CLDMV/fix-headers/pull/166))

The header is now the first thing in the file, except for lines already at the very top that would break the file or its tooling if moved: a `#!` shebang (JavaScript/TypeScript, Python, Rust scripts), a PEP 263 encoding line, `#cloud-config`, `@charset`, `//go:build` / `// +build` constraints, the `<?php` line, Markdown front matter, and a vi/Vim/ex modeline in any comment style. Nothing further down is moved up.

- **Earlier output is repaired.** When an earlier version wrote the header above one of these lines (`#!/usr/bin/env python3`, header, `# -*- coding: utf-8 -*-`), the line moves back up to join the others and the header is rewritten below them. A byte-order mark left below a header goes back to byte 0.
- **Modelines are recognised by Vim's grammar.** Only real `vi:`/`vim:`/`ex:` modelines stay above a `#` header; prose such as `# vi: is the editor we use` is header text.
- **PHP templates are skipped.** A PHP file that does not open with `<?php` is skipped and reported, because a comment at the top would be output as text. A file where only a fix-headers header comes before `<?php` is repaired instead.

### `#` headers in CRLF and byte-order-mark files ([#166](https://github.com/CLDMV/fix-headers/pull/166))

A `#` header in a file with CRLF line endings or a UTF-8 byte-order mark was not found, so a second header was added above it. It is now found and updated in place. The header is written in the file's own line ending, a header an earlier version wrote with `\n` into a CRLF file is rewritten with CRLF, and the byte-order mark stays at the start of the file, ahead of the header and any shebang.

### Entry files and the development check ([#165](https://github.com/CLDMV/fix-headers/pull/165), fixes [#157](https://github.com/CLDMV/fix-headers/issues/157) and [#158](https://github.com/CLDMV/fix-headers/issues/158))

- **Entry files.** The ES module entry is `src/index.mjs` (was `src/fix-header.mjs`) and the CommonJS wrapper is its sibling `src/index.cjs` (was `src/cjs/index.cjs`), so `require("./index.mjs")` resolves the same way from source and from `dist/`. The published `dist/index.mjs`, `dist/index.cjs` and `bin/fix-headers.mjs` paths and the package's exports are unchanged. The `fix-headers-dev` condition now covers `require` as well as `import`.
- **Development check.** A source checkout run without `--conditions=fix-headers-dev` would silently use a stale `dist/` build. The entry now loads a root `devcheck.mjs` first, synchronously, which stops the process with a message saying how to run it. The file is never published, so installed copies skip it. It is loaded through `process.getBuiltinModule`, with no static `node:module` import and no top-level await, so the entry stays safe for bundlers and keeps working through `require()`.

### Linear-time text checks (CodeQL [#1](https://github.com/CLDMV/fix-headers/security/code-scanning/1), [#2](https://github.com/CLDMV/fix-headers/security/code-scanning/2), [#165](https://github.com/CLDMV/fix-headers/pull/165), [#166](https://github.com/CLDMV/fix-headers/pull/166))

The check for an existing `<…>` tag in the author name and the trailing-slash trim on folder paths used regular expressions that backtrack polynomially on long runs of `<` or `/`. Both are now index scans with the same results. The copyright-holder and modeline matching added in this release are linear-time too.

## Upgrade notes

- No breaking change to the `fixHeaders` API or the CLI. The result gains a `copyrightWarnings` array, which is always present.
- **Node.js 22.13.0 or later is required** (was 22.12.0).
- **Expect a one-time diff** in files with a stacked or duplicated header, a stale `@Copyright` line, a block v2.2.3 moved below the header with its lead line, a header above a shebang or directive, or a CRLF or byte-order-mark `#` file that got a second header. Run with `--dry-run --diff` first to review it.
- In a fix-headers source checkout, run the source with `node --conditions=fix-headers-dev`; the npm scripts already do.
